# F-04 路由守卫与按钮级权限控制实施计划

## Summary

- 基于现有 `frontend/` 实现平台级路由守卫、菜单级入口校验、按钮级权限状态，不新增后端接口。
- 视觉继续沿用 F-01/F-02/F-03 的深色 SaaS dashboard 风格：暗底、玻璃面板、蓝色主状态、琥珀锁定态、红色拒绝态、Lucide 图标。
- 权限来源以 `GET /api/auth/me` 返回的 `snapshot.permissionCodes / roleCodes` 为准；后端仍是最终安全边界，前端只做导航与交互防误触。
- 完成后提交并推送到 `origin/feature/F-01-F-03-frontend-portal-auth`。

## Key Changes

- 权限模型：新增 `UserPermissionSnapshot`、`RoutePermissionMeta`、`PermissionCheckResult`、`ButtonPermissionConfig`，统一描述路由与按钮所需权限。
- 权限工具：新增 helper，从用户快照安全提取 `permissionCodes / roleCodes`，提供 `hasPermission`、`hasAllPermissions`、`checkPlatformEntry`、`checkPlatformRoute`。
- 权限映射：`MGMT -> ENTRY:MGMT + MENU:ASSET:READ`，`EMGC -> ENTRY:EMGC + MENU:WORKORDER:READ`，`DIAG -> ENTRY:DIAG + MENU:MODEL:READ`。
- 路由守卫：`/mgmt`、`/emgc`、`/diag` 增加 `requiresAuth / entryPermission / menuPermission`；未登录回 Portal，缺权限进入 `/forbidden`。
- Portal：三平台入口保持可见；无 `ENTRY:*` 的平台卡片置灰锁定，展示缺失入口权限。
- 平台占位页：增加按钮级权限预览，读/写/派单/模型发布按钮按权限启用或禁用，不承载真实业务编辑。

## Public APIs / Interfaces

- 不新增后端接口。
- 前端运行时使用：
  - `GET /api/auth/me`：读取当前用户权限快照。
  - `GET /api/menu-boundaries`：同步平台边界与 `allowWrite` 展示。
- README 联调引用：
  - `GET /api/authz/users/{userId}/snapshot`
  - `POST /api/authz/check`

## Test Plan

- 静态检查：`cd frontend && npm run typecheck`、`cd frontend && npm run build`。
- 未登录访问 `/mgmt`、`/emgc`、`/diag`：回到 `/portal?auth=required&redirect=<target>`。
- 无对应 `ENTRY:*`：Portal 卡片锁定，直接访问路由进入 `/forbidden`。
- 有入口但缺菜单权限：路由拒绝并展示缺少的 `MENU:*`。
- 有读权限无写权限：平台页可进入，写按钮置灰并说明缺少权限。
- 刷新权限快照后，卡片与按钮状态同步更新。

## Assumptions

- F-04 只做前端路由与按钮权限表达，真实业务接口仍由后端注解与 `AuthzGuardAspect` 强制拦截。
- 无权限平台入口采用“显示锁定”方案，不隐藏。
- 本次不实现按钮级权限的服务端实时逐按钮校验、路由权限缓存失效推送、WebSocket 权限刷新；这些留给后续业务页或 F-11。
- `backend/src/main/resources/data.sql` 是既有无关脏改动，不纳入本次提交。

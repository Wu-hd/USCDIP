# F-05 2D 一张图主页面实施计划

## Summary

- 在现有 Vue 前端新增综合管理平台 GIS 主页面 `/mgmt/gis`，保留 `/mgmt` 占位页并增加入口。
- 使用 Leaflet 作为 2D 地图引擎，默认不接外部瓦片，以深色网格底图 + 后端 GIS 对象矢量层完成主链路。
- 与后端 B-10 GIS 接口联调：`GET /api/gis/objects/bbox`、`POST /api/gis/objects/pick`、`GET /api/gis/objects/{objectType}/{objectId}`。
- 继续沿用 F-01~F-04 的暗色数据密集 dashboard 风格：玻璃面板、蓝色空间数据主态、琥珀选中态、红色错误态、Lucide 图标。
- 完成后提交并推送到 `origin/feature/F-01-F-03-frontend-portal-auth`。

## Key Changes

- 地图页面：新增 `/mgmt/gis` 懒加载路由，权限沿用 `ENTRY:MGMT + MENU:ASSET:READ`。
- 地图布局：顶部状态栏、左侧图层插槽、中心 Leaflet 地图容器、右侧对象详情抽屉、底部事件联动插槽。
- 初始 bbox：`120.15,30.27,120.18,30.30`，请求 `authoritySrid=EPSG:4490&displaySrid=EPSG:4490&page=1&pageSize=50`。
- GIS 类型与服务：新增 bbox 查询、对象点查、对象详情查询，复用统一 token refresh 与路由守卫。
- WKT 解析：支持 `POINT` 与 `LINESTRING`；无法解析的对象保留在列表统计中，但不绘制到地图。
- 图层插槽：先支持 `NODE / SEGMENT / FACILITY / DEVICE` 显隐，透明度、图例和持久化留给 F-06。
- 详情抽屉：展示对象类型、对象链主键、regionId、bbox、anchorPoint、relatedObjectIds、attributes、traceId。

## Public APIs / Interfaces

- 新增前端依赖：`leaflet`、`@types/leaflet`。
- 后端接口不变：
  - `GET /api/gis/objects/bbox?minX&minY&maxX&maxY&authoritySrid=EPSG:4490&displaySrid=EPSG:4490&objectType&page&pageSize`
  - `POST /api/gis/objects/pick`
  - `GET /api/gis/objects/{objectType}/{objectId}?displaySrid=EPSG:4490`
- 路由约定：
  - `/mgmt/gis` 是 F-05 2D GIS 主页面。
  - `/mgmt` 保留平台占位页，并提供进入“一张图”的按钮。

## Test Plan

- 静态检查：`cd frontend && npm run typecheck`、`cd frontend && npm run build`。
- 未登录访问 `/mgmt/gis`：回到 Portal 登录提示。
- 无 `MENU:ASSET:READ`：进入 `/forbidden`。
- 有权限访问 `/mgmt/gis`：bbox 对象绘制到地图，数量与接口 total 对齐。
- 点击矢量对象：高亮并打开详情抽屉。
- 点击地图空白：调用 pick，未命中展示空结果提示。
- 对象详情接口 401/403/404/5xx：抽屉或状态条显示错误与 traceId，不崩溃。

## Assumptions

- F-05 只实现 2D 主页面骨架、对象渲染、选中与详情抽屉；F-06 再做图层透明度、图例和持久化。
- 默认不接公网瓦片，避免环境依赖；后续可通过环境变量扩展瓦片 URL。
- 前端使用后端返回的 `EPSG:4490` 展示坐标，不在浏览器端自行做 SRID 转换。
- 3D 仅保留降级说明，不在本次实现。
- `backend/src/main/resources/data.sql` 是既有无关脏改动，不纳入本次提交。

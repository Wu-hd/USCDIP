# F-08 资产详情抽屉实施计划

## Summary

- 将 `/mgmt/gis` 右侧对象详情抽屉升级为多标签资产上下文面板，覆盖基础档案、关联设备、历史告警、事件、工单。
- 视觉沿用 F-05~F-07 深色 SaaS analytics dashboard 风格：紧凑信息密度、玻璃面板、蓝色数据态、琥珀联动态、红色风险态与 Lucide 图标。
- 不新增后端接口，基于现有 GIS、主数据、设备台账、告警、事件、工单 API 组合联调。
- 对象链关联项可点击切换对象，并复用现有地图定位与详情抽屉联动。

## Key Changes

- 抽屉结构：新增 `基础档案 / 关联设备 / 历史告警 / 事件 / 工单` 标签页，保留对象标题、类型、region、定位按钮和 traceId。
- 基础档案：合并展示 GIS 详情、主数据详情、空间字段、bbox、anchorPoint、对象链和 attributes。
- 关联设备：按当前对象类型查询设备台账；DEVICE 展示自身详情，NODE/SEGMENT/FACILITY 使用对应过滤条件聚合设备。
- 告警与事件：以关联设备为主线并发查询 `/api/alerts`、`/api/incidents`，按主键去重后在 tab 内展示。
- 工单：先聚合事件，再按 `incidentId` 查询 `/api/workorders`；缺少 EMGC 工单权限时只影响工单 tab。

## Public APIs / Interfaces

- 使用现有后端接口：
  - `GET /api/gis/objects/{objectType}/{objectId}?displaySrid=EPSG:4490`
  - `GET /api/master/nodes|segments|facilities|devices/{id}`
  - `GET /api/device-ledger/devices` 与 `GET /api/device-ledger/devices/{deviceId}`
  - `GET /api/alerts?page=1&pageSize=20&deviceId=...`
  - `GET /api/incidents?page=1&pageSize=20&deviceId=...`
  - `GET /api/workorders?page=1&pageSize=20&incidentId=...`
- 前端新增类型：`DeviceLedgerResponse`、`IncidentResponse`、`AssetDetailTab`、`AssetDetailTabState`、`AssetDetailContext`。
- 前端新增 service：`deviceLedger.ts`、`incidents.ts`、`workorders.ts`；扩展 `alerts.ts` 和 `masterData.ts` 查询能力。

## Test Plan

- 静态检查：`cd frontend && npm run typecheck`、`cd frontend && npm run build`。
- 选中 `NODE-001 / SEG-001 / FAC-001 / DEV-001`，抽屉应显示基础档案并可切换 tab。
- 关联设备 tab：非设备对象可展示关联设备，设备对象展示自身台账；点击关联对象可切换并定位。
- 历史告警和事件 tab：按关联设备聚合数据，空结果显示明确空态，不影响其他 tab。
- 工单 tab：有 EMGC 权限时展示聚合工单；无权限时仅当前 tab 显示错误与 traceId。
- 任一 tab 401/403/404/5xx 时，抽屉整体不崩溃。

## Assumptions

- F-08 不新增后端聚合接口；跨对象聚合以“关联设备”为主线。
- F-08 不实现 F-12 的独立事件详情页/工单详情页，也不实现工单状态操作。
- tab 数据按当前对象 key 缓存；切换对象后清空旧上下文，避免数据串台。
- `backend/src/main/resources/data.sql` 是既有未提交改动，不纳入本次提交。

# F-13 派单与回写弹窗 - 实施计划

## 1. 目标
在现有 `/emgc/workorders/:id` 工单详情页补齐派单、转派与误报/漏报回写能力，打通“事件 -> 工单 -> 派单 -> 回写”的前端闭环。

## 2. 设计规范
- 使用 `ui-ux-pro-max` 的 SaaS 运维 Dashboard 思路：紧凑信息密度、明确状态胶囊、蓝色信息层级、琥珀色关键操作。
- 弹窗采用两栏结构：左侧表单操作，右侧展示当前工单 ID、状态、处理人、对象链和审计提示。
- 所有按钮使用 lucide 图标，并提供 loading、成功、错误、traceId 和权限不足状态。

## 3. 前后端联调契约
- 派单：`POST /api/workorders/{workOrderId}/dispatch`
  - 请求体：`assigneeUserId / assignee / slaDueAt / reason`
  - `assignee` 必须非空，否则后端 `@NotBlank` 校验会拒绝。
- 转派：`POST /api/workorders/{workOrderId}/transfer`
  - 与派单使用同一请求体，支持从 `DISPATCHED / ACCEPTED` 回到 `DISPATCHED`。
- 回写：`POST /api/workorders/{workOrderId}/writeback`
  - 请求体：`writebackType / writebackReason`
  - 回写独立记录 `writeback_type / writeback_reason / writeback_at`，不等同关闭工单。
- 关闭：`POST /api/workorders/{workOrderId}/close`
  - 前端只提交 `closeReason`，避免将回写语义混入关闭动作。

## 4. 实现内容
- 扩展前端 `WorkOrderDispatchRequest`，补齐 `assignee / slaDueAt / reason`。
- 更新 `dispatchWorkOrder`、`transferWorkOrder`、`closeWorkOrder` API 方法。
- 新增 `WorkOrderActionModal.vue`，支持派单、转派、回写三种模式。
- 在 `WorkOrderDetailView.vue` 中按状态和权限展示操作入口：
  - `CREATED`：派单
  - `DISPATCHED / ACCEPTED`：转派
  - 具备 `MENU:WORKORDER:DISPATCH`：回写
- 当前后端暂无巡检人员列表接口，一期使用种子巡检人员 `U-INSPECT-001 / zhangsan / 巡检人员张三`，并提供自定义处理人输入。

## 5. 验收与测试
- `npm run typecheck`
- `npm run build`
- 使用调度员权限打开 `WO-002`，派单到 `zhangsan`，确认 `status / assignee / slaDueAt / dispatchedAt` 更新。
- 对已派单工单转派，确认请求体包含 `assignee`。
- 提交 `FALSE_POSITIVE / MISSED_REPORT / OTHER` 回写，确认工单状态不会被改为 `CLOSED`。
- 未填处理人、未填回写原因、缺少派单权限时，应展示明确提示。
